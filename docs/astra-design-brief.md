# ТЗ для Astra: визуальная доработка DreamApt

- **Исполнитель:** агент Astra (Codex). Работу контролирует локальная сессия Claude Code.
- **Репозиторий:** `glymskii/DreamApt`, монорепо на pnpm (`apps/frontend`, `apps/backend`, `packages/shared`).
- **Базовая ветка:** `claude/enrich-database-residential-complexes-zqvbpr`. В ней уже есть первый черновик панели ключевых фич (п. 4).
- **Зона работы:** визуальная часть публичной карты и связанных с ней экранов. Бэкенд и логику не трогать.

## 1. Задача

DreamApt — публичная карта жилых комплексов (ЖК) Алматы для тех, кто выбирает квартиру. Ключевых фич четыре:
**сейсмика, качество воздуха, новостройки, генплан**. «Новостройки» на карте — это два фильтра: «Строящиеся» и «Новостройки» (недавно сданные). Технически всё уже работает, но выглядит как служебные слои, а не как главное, ради чего приходят на сайт.

Нужно, чтобы любой пользователь, на телефоне и на компьютере, с первого экрана видел эти фичи, понимал, что каждая показывает, и мог включить или выключить любую. Интерфейс должен выглядеть цельно: одни цвета и иконки для фичи везде, где она появляется.

## 2. Продукт

- Главная страница — `/dashboard`, `/` перенаправляет туда. На ней:
  - шапка;
  - слева список ЖК с поиском и фильтрами (на телефоне открывается кнопкой-лупой);
  - справа карта MapLibre;
  - карточка ЖК по клику: справа на компьютере, нижней шторкой на телефоне.
- Пользователи — покупатели квартир в Алматы. Многие заходят с телефона и впервые: для них есть онбординг-диалог.
- Языки: русский (по умолчанию) и казахский. Казахские строки обычно длиннее. Темы: светлая и тёмная.
- Объём данных: 600–1000 ЖК на карте. Строящихся после деплоя бэкенда из базовой ветки и повторной синхронизации будет около 110. До этого на проде помечено 613: там есть старые ЖК, см. п. 4.
- Новостройки — ЖК, сданные за последние три года. В 2026 году это 2023–2026.
- Есть ещё карта проекта поиска `/projects/[id]/map`. Она использует тот же `MapView`, но без списка.

## 3. Четыре ключевые фичи

**Главное правило.** «Сейсмика», «Воздух» и «Генплан» — **слои**: показывают или скрывают слой на карте и не фильтруют ЖК. «Строящиеся» и «Новостройки» — **только фильтры** точек ЖК: на карте и в списке остаются подходящие ЖК, слои не меняются. Если включены оба фильтра, показываются и те и другие.

### Сейсмика

- **На карте:** линии разломов и зоны риска (`faults-lines-1..3`, `risk-zone-low|moderate|high`). Цвет каждой точки ЖК — уровень сейсмориска: safe `#22c55e`, low `#84cc16`, moderate `#eab308`, high `#f97316`, critical `#dc2626`.
- **По умолчанию:** включена.
- **Где ещё:** фильтр «Близость к разлому» в списке; в карточке ЖК блок сейсмики (расстояния до подтверждённых, изученных и спорных разломов плюс дисклеймер); легенда.
- **Код:** `MapView.tsx`: `SEISMIC_LAYERS`, `getSeismicColor`.

### Воздух (PM 2.5)

- **На карте:** тепловая карта по датчикам (`air-heatmap`, рисуется только при 10 и более станциях) и станции в виде «бубликов» (`air-stations-circles`).
- **По умолчанию:** включён.
- **Где ещё:** в карточке ЖК блок качества воздуха (PM 2.5) и график по часам и дням недели; легенда уровней PM.
- **Код:** `MapView.tsx` (`AIR_LAYERS`), `components/complex/AirHistoryChart.tsx`.

### Строящиеся

- **На карте:** фильтр точек — остаются ЖК с `constructionStatus = "under_construction"`. Сюда не входят ЖК, у которых срок сдачи раньше прошлого года. У строящихся ЖК голубое кольцо `#0284c7` при любом состоянии фильтра.
- **По умолчанию:** выключен.
- **Где ещё:**
  - чип «🏗 Строящиеся» в фильтрах списка, у него общее состояние с кнопкой на карте;
  - бейдж «Строится · срок» в списке;
  - строка во всплывающей подсказке;
  - блок «Строится» в карточке ЖК: срок сдачи, застройщик, класс, предупреждение о просроченном сроке.
- **Код:** `MapView.tsx` (`markerFilter`, свойство точки `underConstruction`), `hooks/useComplexFilters.ts`, `lib/construction.ts` (`isUnderConstruction`).

### Новостройки

- **На карте:** фильтр точек — ЖК, сданные за последние три года. Год берётся поздний из двух: год постройки из объявлений (`yearBuilt`) или срок сдачи с Krisha (`completionYear`); будущие годы не считаются. Строящиеся сюда не входят. Отдельного кольца на карте у новостроек пока нет.
- **По умолчанию:** выключен.
- **Где ещё:** чип «🏠 Новостройки» в фильтрах списка, бейдж «Новостройка · год» в списке, строка «Новостройка · сдан в …» во всплывающей подсказке.
- **Код:** `lib/construction.ts` (`isNewBuilding`, `completedYear`, `NEW_BUILDING_YEARS = 3`), свойство точки `newBuilding` в `MapView.tsx`.

### Генплан

- **На карте:** растр «Детальный генплан» (`genplan-detailed-img`, файл `/genplan-detailed.webp`). Конфиг оверлея приходит в `map-data.overlays`.
- **По умолчанию:** выключен.
- **Где ещё:** подпись в легенде «Подготовил эксперт Тихон Шутов». Она обязательна.
- **Код:** `MapView.tsx`: `GENPLAN_LAYERS`.

### Проблемные ЖК

Отдельно от четырёх фич — **проблемные ЖК по данным акимата**: крупная малиновая точка с тёмным кольцом и баннер «акимат не рекомендует покупку» в карточке. Это самый сильный предупреждающий сигнал продукта, он должен остаться самым заметным.

## 6. Ограничения

- **Логика.** Не менять бэкенд, API, данные, формулы скоринга, сейсмики и качества воздуха, смысл фильтров. Правило из п. 3 (слои — это не фильтр) не менять.
- **Админка.** Не трогать `/admin`, кроме общих компонентов, если без этого никак.
- **Тексты.**
  - Каждая видимая строка идёт через `t()`, а ключ есть **и** в `src/lib/i18n/locales/ru.json`, **и** в `kk.json`.
  - Неиспользуемые ключи удалять из обоих файлов.
- **Карта.**
  - Не пересоздавать экземпляр MapLibre при изменении состояния интерфейса.
  - Слои переключать через `setLayoutProperty`, точки — через `setFilter` и `setPaintProperty`.
  - Механизм `layersRef` и `markerFilterRef` сохранить.
- **Безопасность.** Всплывающие подсказки собираются из DOM-узлов с `textContent` (хелпер `el()`). Данные из внешних источников никогда не вставлять через `innerHTML`.
- **Стек не меняется.**
  - Next.js 16.2 (App Router), React 19, Tailwind 3.4.
  - Компоненты в стиле shadcn в `src/components/ui`, Radix Dialog.
  - lucide-react 1.7, maplibre-gl 5.22, @tanstack/react-query, react-i18next.
  - Новые UI-библиотеки не подключать. Если нужен новый примитив, сделать его отдельным компонентом в `src/components/ui`.
- **Доступ по авторизации.** Время до работы, рейтинг Шутова и список квартир показываются по тем же правилам, что сейчас.
- **Атрибуция генплана.** Подпись «Подготовил эксперт Тихон Шутов» не убирать.

## 7. Критерии приёмки

- **Первый экран.** На 1440×900 и 390×844 без единого клика видно все ключевые фичи, они подписаны, их состояние понятно. Ничего не перекрывает кнопки зума и друг друга.
- **Поведение.**
  - Переключение любой фичи не сбрасывает центр и зум карты.
  - «Строящиеся» и «Новостройки» оставляют на карте и в списке один и тот же набор ЖК; вместе — объединение.
  - Слои не фильтруют ЖК.
- **Темы и языки.** В светлой и тёмной теме, на русском и казахском нет обрезанных подписей. Контраст текста не ниже 4.5:1.
- **Сборка.**
  - Проходят `pnpm --filter frontend exec tsc --noEmit` и `pnpm --filter frontend build`.
  - ESLint по изменённым файлам без новых ошибок. В `MapView.tsx`, `MapSidebar.tsx` и `admin/page.tsx` уже есть 13 старых замечаний, их можно не трогать.
- **Скриншоты до и после:**
  - компьютер, светлая тема;
  - компьютер, тёмная тема;
  - телефон;
  - телефон с открытой карточкой ЖК;
  - казахский язык.

## 8. Как запустить

- Node 24, pnpm 9.15, затем `pnpm install`.
- Фронтенд: `pnpm --filter frontend dev`, откроется http://localhost:3002.
- Адрес API задаёт `NEXT_PUBLIC_API_URL`, по умолчанию `http://localhost:3003/api`.

### Реальные данные

Проще всего смотреть **превью Vercel**. `NEXT_PUBLIC_API_URL` задан и для Preview, поэтому каждый пуш в ветку собирает превью с прод-данными.
- Открывать нужно хеш-адрес вида `dreamapt-<hash>-glymskiis-projects.vercel.app`: его пропускает CORS бэкенда. Адрес ветки вида `dreamapt-git-…` данных не получит.
- Защита деплоев выключена, превью открываются без входа, Playwright тоже работает.
- Хеш-адрес конкретного пуша есть в комментарии Vercel к PR и в Vercel → Deployments.

Локальный фронтенд с прод-данными работает, только если владелец добавит `http://localhost:3002` в `FRONTEND_URL` бэкенда на Render.

**Важно:** превью и фронтенд с прод-API работают с **боевой базой**. Не входить под админом, не нажимать действия админки, не оставлять комментарии и отзывы, не создавать поиски. Только смотреть.

### Без прод-данных

1. Поднять базу: `docker compose up -d postgres`.
2. Собрать общий пакет: `pnpm --filter @dreamapt/shared build`.
3. Запустить бэкенд `pnpm --filter backend dev` с переменными:
   - `DATABASE_URL=postgresql://dreamapt:dreamapt@localhost:5432/dreamapt`;
   - `JWT_SECRET` — любая строка от 32 символов;
   - `ADMIN_PASSWORD`.
4. После первого старта (TypeORM сам создаст таблицы) засеять демо-ЖК SQL-запросом из приложения.

Разломы и конфиг генплана подгрузятся сами. Данные датчиков воздуха бэкенд берёт из интернета.
